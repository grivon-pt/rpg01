# Тёплый Ручей — состояние проекта (передача контекста)

Обновлено: 16.11.2026, 20:00 МСК.

## Что это

Уютная пиксельная RPG для телефона: S.P.E.C.I.A.L. и пошаговые бои в духе Fallout 1/2. Вся игра — один файл `index.html` без внешних зависимостей. Репозиторий: https://github.com/grivon-pt/rpg01 (ветка `main`).

Подробности:
- `README.md` — что уже есть в игре и управление;
- `CLAUDE.md` — устройство кода и правила команды;
- `docs/design/` — дизайн-документы, `docs/art/` — стайлгайд и макеты, `docs/qa/` — отчёты тестов, `tests/` — автотесты Playwright.

## Что сделано

Прототип: деревня с пятью жителями (диалоги с проверками S.P.E.C.I.A.L., торговля, кузнец, травница, задания), луг со слаймами, инвентарь и снаряжение, лук, магия, перки, сохранение, автобой, PWA. Спринт 1 «Шепчущий лес» принят: переходы между картами, два новых врага, мини-босс Древний пень, задание Ефима. Тесты: `tests/test_regression.py`, `test_sprint1_forest.py`, `test_sprint1_stump.py` — все проходят.

## Сейчас

Идёт этап «графика»: новые локации не делаем, улучшаем то, что есть. Ориентиры пользователя по графике — Exiled Kingdoms, Fallout, Arcanum.

**Ждём решения пользователя:** макет А, макет Б или сочетание (например, изометрия из Б и интерфейс со спрайтами из А). После выбора программист переносит стиль в `index.html`, тестировщик прогоняет тесты (в изометрии нужно поправить `cell_client` в `tests/qa_common.py`), руководитель принимает, пушит и публикует в артефакт «прототип».

Оценки переноса: А — 2–4 ч; Б — 1–2 дня, плюс перерисовка персонажей 16×24 в 4 диагональных ракурсах. Подробности — в отчётах в `docs/art/mock-b-notes.md` и `docs/art/style-guide.md`.

Дальше по плану (`docs/design/roadmap-locations.md`): спринт 2 — системы мира (костры быстрого перемещения, мини-карта), затем озеро, ярмарка, шахта, пещеры, башня мага.

## Как работает команда

Роли — в `.claude/agents/`: lead, designer, artist, programmer, tester. Руководитель — главный чат: он ставит задачи агентам по цепочке «дизайн → код → тест → исправления → приёмка», сам принимает работу, пушит и публикует. Агентов запускать через инструмент Agent; если тип роли недоступен, использовать `general-purpose` и в задаче попросить прочитать `.claude/agents/<роль>.md`.

Правила:
- Коммиты: `git -c user.name="grivon-pt" -c user.email="grivon-pt@users.noreply.github.com" commit`, сообщение по-русски, в конце строки атрибуции. Агенты не пушат, пушит руководитель.
- При параллельной работе каждый агент делает `git add` только своих файлов.
- Подводные камни Playwright: не возвращать из `page.evaluate` бесконечный промис (`startCombat(...)` — дописать `;0`), `set_default_timeout(8000)`, запускать через `timeout 150 python3 -u -I`.

## Как пользователь хочет работать

- В сообщениях о ходе работы указывать примерное время до результата и сразу сообщать о сдвигах.
- Промежуточные результаты можно присылать на почту через Gmail. Письмо о макетах графики пользователь отменил; перед следующими письмами уточнить, нужны ли они.
- Пользователь хочет периодически видеть результат: публиковать сборки и показывать скриншоты.
