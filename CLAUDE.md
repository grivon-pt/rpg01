# Тёплый Ручей — заметки для команды

Уютная пиксельная RPG для телефона с ролевой системой S.P.E.C.I.A.L. и пошаговыми боями в духе Fallout 1/2. Игра целиком лежит в одном файле `index.html`: HTML, CSS и JS без сборки и внешних библиотек. ТЗ ведётся отдельно у руководителя; краткая сводка того, что уже есть, — в `README.md`.

## Команда

Роли описаны в `.claude/agents/`:
- `lead.md` — руководитель: планирует спринт, раздаёт задачи, принимает работу, пушит, публикует и показывает пользователю;
- `designer.md` — дизайнер: геймдизайн и визуал, пишет документы в `docs/design/`;
- `programmer.md` — программист: реализует в `index.html`, коммитит;
- `tester.md` — тестировщик: проверяет сборку автотестами в `tests/`, пишет отчёты в `docs/qa/`.

Работа идёт по цепочке: дизайн → код → тест → исправления → приёмка.

## Устройство index.html

Разделы в скрипте отмечены комментариями `// ---------- имя ----------`, по порядку:
setup (масштабы S — мир, H — интерфейс), map (генерация карты 48×32 клеток по 16 px и её предрисовка), audio (`snd`), hero & stats (S.P.E.C.I.A.L., перки, объект `D` с производными характеристиками), items (`ITEMS`, иконки, сумка, `getIt` с улучшениями), grid (`walkable`, `findPath`, `los`), movement (`setPath`), timers (`wait`, `until`), save (`localStorage`, ключ `teplyruchey_save_v3`), state, input (`tapCell`, `pickCell`), combat (пошаговый бой: `startCombat`, `makePreview`, `execute`, `enemyTurn`), auto-battle, world entities (`spawnSlime`), update, village (NPC, диалоги `openDlg`, магазин, перераспределение, журнал), character panel, start, drawing (`render`), loop.

## Правила

- Язык интерфейса и коммитов — русский.
- Всё остаётся в одном `index.html`, без внешних скриптов и картинок: графика рисуется кодом (пиксель-арт через `fillRect`).
- Новые поля сохранения добавляются так, чтобы старые сохранения продолжали загружаться.
- Телефон — основная платформа: цели для тапа не меньше клетки, текст интерфейса через `otext(…, sc)` в масштабе `H`.
- Перед коммитом: `node --check` на извлечённый скрипт и прогон тестов из `tests/`.
- Коммиты делает программист (или тестировщик — только тесты и отчёты). Пушит и публикует руководитель.
